# Replaying historical research artifacts

Archived research results are immutable evidence. Their manifests can include
hashes of the entire source tree and the original protocol text, beyond the
files that directly implement numerical dynamics. Current scope and terminology
edits therefore change the context even when all experimental numbers and
parameters remain unchanged.

Do not refresh old manifests or weaken a context check to make an old result
appear to have been generated by today's code. Use the revision and environment
documented in the result report. Original protocol wording remains available
in Git history; current protocol pages retain the numerical design with editorial
terminology updates only.

For the archived Phase 6 run, revision `503aa9e` contains the complete execution
code, protocol and results. In a separate clone of this repository:

```powershell
git checkout --detach 503aa9e
python -m venv .venv-phase6
.\.venv-phase6\Scripts\python.exe -m pip install -r requirements-phase6-lock.txt
$env:PYTHONPATH = "src"
.\.venv-phase6\Scripts\python.exe -m flying.training.phase6 verify --out results/phase6
.\.venv-phase6\Scripts\python.exe -m flying.training.phase6 prepare
.\.venv-phase6\Scripts\python.exe -m flying.training.phase6 run --out outputs/phase6_replay
.\.venv-phase6\Scripts\python.exe -m flying.training.phase6 verify --out results/phase6 --compare outputs/phase6_replay
```

Current code can generate new research runs in fresh output directories, with
its own context and manifests. The archived Phase 6 verifier is expected to
reject a changed current source context. This is intentional provenance checking,
not evidence that the saved numerical arrays changed. The same rule applies to
other historical experiments that use strict context checks.
